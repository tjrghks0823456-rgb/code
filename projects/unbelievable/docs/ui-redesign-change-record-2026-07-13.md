# UI 수정 기록본 - 2026-07-13

## 목적

Unbelievable 프로젝트의 첫 진입 화면, 설문, 결과, 미션 흐름을 더 읽기 쉽고 접근하기 쉬운 구조로 정리했다. 특히 디톡스 미션은 단순 추천 목록이 아니라, 미션 전후 변화를 비교하는 과정이라는 점이 화면에서 보이도록 개선했다.

## 수정 원칙

- 첫 화면에서는 사용자가 바로 무엇을 해야 하는지 알 수 있게 한다.
- 설문과 업로드는 큰 버튼과 단계 안내를 중심으로 접근성을 높인다.
- 분석 결과 화면은 처음부터 모든 세부 정보를 펼치지 않고, 핵심 결과와 전후 비교를 먼저 보여준다.
- 미션 화면은 "미션 전 분석 -> 미션 수행 -> 미션 후 재분석"의 흐름을 명확히 보여준다.
- 기존 백엔드 API 구조는 건드리지 않고 프론트엔드 UI 중심으로 수정한다.

## 파일별 수정 내용

### `frontend/src/components/PageShell.tsx`

- 상단 내비게이션 라벨을 읽기 쉬운 한국어로 정리했다.
- 홈, 자가진단, 기록 업로드, 결과, 미션 이동 흐름이 한눈에 보이도록 메뉴 순서를 재구성했다.
- 하단 문구를 디톡스 전후 비교 목적에 맞게 수정했다.

### `frontend/src/app/page.tsx`

- 첫 진입 화면을 서비스 소개보다 실제 행동 중심으로 재구성했다.
- 주요 CTA를 `실제 기록 업로드`, `자가진단 먼저 하기`로 정리했다.
- 오른쪽 미리보기 패널에 미션 전후 비교가 핵심이라는 메시지를 배치했다.
- 자가진단, Takeout 업로드, 결과 확인, 미션 후 비교까지 4단계 여정을 카드로 보여주도록 수정했다.
- 관심사 지도, 전후 변화, 데이터 신뢰도 등 결과에서 확인할 수 있는 항목을 간단한 예고 카드로 정리했다.

### `frontend/src/app/survey/page.tsx`

- 깨져 있던 설문 문구를 정상 한국어로 복구했다.
- 16개 문항을 4단계로 나누어 한 번에 4개씩만 보이도록 유지하면서 설명을 더 명확하게 바꿨다.
- 선택 버튼에 `aria-pressed`를 유지해 선택 상태를 보조 기술에서도 인식할 수 있게 했다.
- 현재 단계 응답 진행률과 남은 문항 안내를 더 읽기 쉬운 문구로 수정했다.
- 설문 결과 후 `다시 진단하기`, `홈으로`, `실제 기록과 비교하기` CTA를 명확하게 배치했다.
- 백엔드 저장은 실패해도 로컬 결과가 사라지지 않도록 비동기 동기화 주석을 남겼다.

### `frontend/src/app/dashboard/page.tsx`

- 결과 상단에 `디톡스 미션 전후 변화` 비교 섹션을 추가했다.
- 현재 분석 결과를 브라우저 localStorage에 스냅샷으로 저장하도록 했다.
- 다음 분석이 들어오면 이전 분석과 현재 분석을 비교해 변화량을 보여준다.
- 비교 항목은 정보 편향 위험도, 최종 디톡스 위험, 숏츠 반복 위험, 관심사 다양성, 사용자 주도성, 관심사 불일치로 구성했다.
- 위험 점수는 낮아질수록 좋아 보이게, 다양성/사용자 주도성은 높아질수록 좋아 보이게 표시했다.
- 미션 시작 버튼을 비교 섹션 안에도 배치해 결과 확인 이후 다음 행동으로 이어지게 했다.

### `frontend/src/app/mission/page.tsx`

- 미션 화면을 "미션 전 -> 미션 수행 -> 미션 후" 흐름 중심으로 재구성했다.
- 오늘의 진행률과 완료한 미션 수를 상단에서 바로 확인할 수 있게 했다.
- 미션 후 다시 분석 버튼을 추가해 전후 비교 루프가 자연스럽게 이어지도록 했다.
- 직접 검색 미션과 일반 미션 카드를 분리해 사용자가 무엇을 실행해야 하는지 더 쉽게 이해할 수 있게 했다.

## 검증 기록

- `projects/unbelievable/frontend` 기준 `tsc --noEmit` 타입 검사를 통과했다.
- `next build`는 현재 Windows 실행 환경에서 `spawn EPERM` 오류가 발생해 완료하지 못했다. 이전에도 동일하게 관찰된 환경성 빌드 제한으로 보고, 타입 검사를 1차 검증 기준으로 삼았다.
- `github-sync/dash-target` 저장소는 `node_modules`가 없어 직접 타입 검사를 수행하지 않고, 동일 파일을 실제 실행 프로젝트에 동기화한 뒤 검증했다.

## 남은 개선 후보

- 대시보드 기존 세부 분석 영역에는 과거 깨진 문구와 높은 정보 밀도가 일부 남아 있다.
- 다음 단계에서는 대시보드 세부 카드들을 접힘 영역으로 더 정리하고, 관심사 맵을 방사형 그래프 형태로 다시 구성하는 작업이 필요하다.
- 업로드 화면도 첫 사용자 기준으로 Google Takeout 준비 방법, 분석 대상 폴더, 오류 해결 안내를 더 시각적으로 정리할 수 있다.
